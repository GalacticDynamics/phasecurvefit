# Migrating from v0.3 to v0.4

In v0.4 the default ordering pipeline is **an MST backbone refined by a SOM**.
`pcf.order(positions, velocities)` with no orderer used to run the
velocity-following local-flow walk; it now runs
{func}`~phasecurvefit.orderers.default_pipeline`, i.e.
`MSTOrderer(...) | SOMOrderer(...)`. This is a **breaking change** to the package's
primary entry point. Code that passes an orderer explicitly is unaffected.

v0.4 also **removes `pcf.walk_local_flow`**, which has warned since v0.3.1; see
[below](#walk-local-flow-is-removed).

```{warning}
If you call `pcf.order(pos, vel)` without an orderer, your results change. If you
call `pcf.walk_local_flow`, it no longer exists. In both cases, to get the v0.3
walk, name it yourself:

`pcf.order(pos, vel, pcf.orderers.LocalFlowOrderer())`
```

## What changed, and why

The SOM is a smoothing stage: its prototypes average over many tracers, so the
backbone it produces is far less sensitive to local noise than a greedy walk's
step-by-step choices. The MST ahead of it needs no progenitor or start index — the
graph diameter finds the two ends of the curve itself — and handles near-closed
loops where the velocity field reverses. Together they work on more data with
fewer decisions from you, which is what a default should do. See the
[Orderers guide](../guides/orderers) and the [SOM guide](../guides/som).

## Keeping the walk

The v0.3 default is one explicit argument away, and reproduces it exactly:

```python
import jax.numpy as jnp
import phasecurvefit as pcf

pos = {"x": jnp.array([0.0, 1.0, 2.0, 3.0, 4.0])}
vel = {"x": jnp.ones(5)}

# v0.3: the default. v0.4: name it.
walk = pcf.order(pos, vel, pcf.orderers.LocalFlowOrderer())
assert isinstance(walk, pcf.WalkLocalFlowResult)
assert walk.gamma_range == (0.0, 1.0)
```

Walk parameters (`start_idx`, `metric_scale`, `direction`, `config`, …) live on
`LocalFlowOrderer(...)`, exactly as they did for v0.3's explicit form.

## What the new default returns

| | v0.3 default (walk) | v0.4 default (MST \| SOM) |
| --- | --- | --- |
| Result type | `WalkLocalFlowResult` | {class}`~phasecurvefit.orderers.OrderingResult` |
| `gamma_range` | `(0.0, 1.0)` | `(-1.0, 1.0)` |
| Needs a start index | yes (`start_idx`) | no |
| `backbone` | `None` | a fitted polyline, which `result(gamma)` interpolates along |
| `chord` | distance along the walk's path | arc length along the fitted backbone |
| Tracers left unvisited | those the walk skipped | none, unless the kNN graph is disconnected (then the largest piece is ordered, with a warning) |
| `jit` / `vmap` | yes | **no** — see below |

Things to check in code that consumed the old default:

- **Type checks.** `isinstance(result, WalkLocalFlowResult)` is now false.
  `WalkLocalFlowResult` subclasses `OrderingResult`, so annotate and check against
  `OrderingResult` to accept either.
- **A hard-coded `gamma_range`.** Read it off the result
  (`result.gamma_range`) rather than assuming `(0.0, 1.0)`; the autoencoder
  already does (`PathAutoencoder.make(..., gamma_range=result.gamma_range)`).
- **Direction.** The default orients `gamma` along the mean velocity
  (`orient_by_velocity=True`), so a stream ordered "with the flow" still is.
- **Cost.** The SOM adds `n_epochs` (default 10) batch-Kohonen passes over the
  visited tracers, so `order()` is no longer free to call in a tight loop.

## Small inputs fall back to the MST

The SOM needs at least `n_prototypes` (default 15) tracers to bin. Rather than
raise on small inputs — the library's own examples are five points — the default
skips the SOM stage and returns the MST ordering alone:

```python
import jax.numpy as jnp
import phasecurvefit as pcf

pos = {"x": jnp.array([0.0, 1.0, 2.0])}
vel = {"x": jnp.array([1.0, 1.0, 1.0])}

result = pcf.order(pos, vel)  # 3 < 15 tracers: MST alone
assert result.gamma_range == (-1.0, 1.0)
assert result.indices.tolist() == [0, 1, 2]
```

Both stages report `gamma_range == (-1.0, 1.0)`, so the fallback is invisible to
code that reads it off the result.

## The default does not trace under jit or vmap

Whether to run the SOM depends on how many tracers the MST visited, which is only
known once it has run. So `pcf.order(pos, vel)` with no orderer raises a
`TypeError` inside `jax.jit` or `jax.vmap` (in v0.3 the walk default traced). Name
an orderer that traces instead:

```python
import jax
import jax.numpy as jnp
import phasecurvefit as pcf

t = jnp.linspace(0.0, jnp.pi, 40)
pos = {"x": 5.0 * jnp.cos(t), "y": 5.0 * jnp.sin(t)}
vel = {"x": -jnp.sin(t), "y": jnp.cos(t)}

walk = pcf.orderers.LocalFlowOrderer()
chord = jax.jit(lambda q, p: pcf.order(q, p, walk).chord)(pos, vel)
```

`MSTOrderer` alone traces too. A SOM stage chained after another stage does not;
see the [SOM guide](../guides/som) and the
[JAX Integration guide](../guides/jax-integration).

## Tuning the default

The default's MST stage is configured to work on data of any scale, not to be
tuned: `jump_cap=inf`, `orient_by_velocity=True`, `on_disconnected="warn"`. It
deliberately does **not** use `MSTOrderer()`'s own defaults — `jump_cap=3.0` is an
absolute length, and severs every edge of a sparse or large-scale dataset.
`default_pipeline` takes `n_prototypes` and any other
{class}`~phasecurvefit.orderers.SOMOrderer` keyword. For anything else — a finite
`jump_cap`, velocity-aware edges, outlier rejection with `edge_clip_sigma` — build
the chain and pass it:

```python
import jax.numpy as jnp
import phasecurvefit as pcf

t = jnp.linspace(0.0, jnp.pi, 60)
pos = {"x": 5.0 * jnp.cos(t), "y": 5.0 * jnp.sin(t)}
vel = {"x": -jnp.sin(t), "y": jnp.cos(t)}

chain = pcf.orderers.MSTOrderer(
    k=8, jump_cap=2.0, edge_clip_sigma=3.0, orient_by_velocity=True
) | pcf.orderers.SOMOrderer(n_prototypes=12)
result = pcf.order(pos, vel, chain)
assert int(result.n_visited) == 60
```

## New in v0.4

- {class}`~phasecurvefit.orderers.SOMOrderer` and the {mod}`phasecurvefit.som`
  module: a Self-Organizing Map ordering stage (Starkman et al. 2023).
- `a | b` and {class}`~phasecurvefit.orderers.ChainOrderer`: run orderers in
  sequence, each receiving the previous result as `init`.
- {func}`~phasecurvefit.orderers.default_pipeline`: the function behind the new
  default.
- {func}`~phasecurvefit.fit_track`: order, refine, and train the autoencoder in one
  call (it uses the default pipeline).

## `walk_local_flow` is removed

`pcf.walk_local_flow`, deprecated since v0.3.1, is gone. Its replacement is the
orderer, with the walk's keyword arguments moved onto `LocalFlowOrderer(...)` — see
[Migrating from v0.2 to v0.3](v0.2-to-v0.3):

<!-- skip: next -->

```python
# v0.3 (deprecated, warns):
result = pcf.walk_local_flow(pos, vel, start_idx=0, metric_scale=1.0)

# v0.4:
result = pcf.order(
    pos, vel, pcf.orderers.LocalFlowOrderer(start_idx=0, metric_scale=1.0)
)
```

Note that `pcf.order(pos, vel)` with no orderer is *not* a replacement: it runs the
default MST | SOM pipeline. The walk's `usys` keyword for Quantity inputs is passed
as `metadata=pcf.StateMetadata(usys=...)` to `order`. `combine_results`,
`order_w` and `WalkLocalFlowResult` are unchanged.

## Compatibility summary

| Symbol | Status |
| --- | --- |
| `pcf.order(pos, vel)` (no orderer) | **Changed**: runs `MSTOrderer \| SOMOrderer`, not the walk |
| `pcf.order(pos, vel, orderer)` | Unchanged |
| `pcf.orderers.LocalFlowOrderer`, `MSTOrderer` | Unchanged |
| `pcf.walk_local_flow` | **Removed** (deprecated since v0.3.1); use `order` with `LocalFlowOrderer` |
| `pcf.WalkLocalFlowResult` | Unchanged; subclasses `OrderingResult` |
| `pcf.combine_results`, `pcf.order_w`, `pcf.WalkConfig`, `pcf.metrics`, `pcf.strats`, `pcf.nn` | Unchanged |
| `pcf.orderers.SOMOrderer`, `ChainOrderer`, `default_pipeline`, `pcf.fit_track`, `pcf.som` | **New** |
