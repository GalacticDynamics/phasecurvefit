What phasecurvefit does#

Many datasets are samples along a curve in phase space whose order along the curve is unknown. A stellar stream is the running example: you have each star’s position and velocity, but not where along the stream it sits. Before you can fit a model to such a curve you need two things: an ordering coordinate for every sample, and a smooth track through the samples.

phasecurvefit produces both. It takes positions and velocities as two dictionaries with matching keys, one array per coordinate, in any number of dimensions:

  • An ordering. order() returns an OrderingResult holding the sample indices in order along the curve, and an ordering coordinate \(\gamma\) that runs from one end of the curve to the other.

  • A smooth track. An autoencoder learns \(\gamma\) for every sample, including any the ordering left out, and a mean track \(x(\gamma)\) that you can evaluate at any \(\gamma\). fit_track() runs the ordering and the fit in one call.

  • Membership. A stream-plus-background mixture model gives each sample a probability of belonging to the curve, for data with interlopers.

The default pipeline#

With no other arguments, pcf.order(pos, vel) runs two stages. A minimum spanning tree of the nearest-neighbour graph gives a backbone whose longest path runs from one end of the curve to the other, so no start point is needed. A one-dimensional self-organizing map then averages over many samples along that backbone, which smooths the ordering against local noise. Both stages weigh position against velocity: two nearby samples moving in different directions are kept apart, so where a curve crosses itself the ordering crosses straight over. The velocities also set the direction, so that \(\gamma\) increases along the flow. On a curve that crosses itself many times, a walk that follows the velocity does better. fit_track() adds the autoencoder on top.

Other orderers can replace either stage. The local-flow walk follows the velocity field from a start point, step by step, and is the better choice when a curve crosses itself. Is phasecurvefit right for my data? matches your data to an orderer.

Built on JAX#

The orderers, distance metrics and neural networks are written in JAX and are Equinox modules. The local-flow walk and the MST orderer work under jit, vmap and grad, and everything runs on CPU or GPU. Inputs may carry physical units through unxt.
